# Clear GPS

**Privacy-first Android radio surveying, local Wi-Fi/Bluetooth/cell-point mapping, and an experimental GNSS anomaly filter.**

Clear GPS is an experimental open-source Android application built with Kotlin, Jetpack Compose, Material 3 and MapLibre Native. Wireless identifiers are collected only when the user starts a scan, and recorded observations stay in the app-private SQLite database. BeaconDB cell-only lookup is **disabled by default**. If explicitly enabled in Settings, a manual lookup sends only supported current cellular identifiers and signal strengths to BeaconDB's geolocation endpoint; Wi-Fi, Bluetooth, GPS coordinates and contribution uploads are not sent. The app never calls BeaconDB's data-submission endpoint and does not query the WiGLE API.

## Features

- **Pixel-inspired Material 3 UI** with dynamic Android 12+ colours, light/dark/system map themes, and explicit scan/status feedback.
- **MapLibre map** using OpenFreeMap styles based on OpenStreetMap data. Includes light Liberty and Dark styles, a blue location dot and accuracy area, a manual amber reference point, coloured radio-point overlays and separately named spoofing-risk zones.
- **Local radio recorder:** manually started scans of nearby Wi-Fi access points (BSSID + RSSI + frequency), available GSM/WCDMA/LTE/NR cell identities and Bluetooth LE addresses/RSSI.
- **Private SQLite database:** Wi-Fi SSIDs and BSSIDs, available cell identifiers, BLE addresses/RSSI, editable labels and coordinates, and bounded observation history. Radio identifiers remain in the app-private database; no radio IDs are uploaded.
- **Radio-only mode:** Clear GPS stops requesting system location providers in the app and estimates a position only when current radio observations match coordinates already recorded in the local database. It does not switch off the GNSS hardware for Android or other apps.
- **WiGLE interchange:** import WiGLE CSV (plain or gzip), WiGLE-style SQLite (`network` / `location` tables), or a Clear GPS SQLite backup. Export individual WiGLE observations as CSV, create a WiGLE-style SQLite database, or create a full Clear GPS backup. Imports merge with the local database and avoid re-adding identical observations.
- **Read-only OBD-II (automatic when available):** In Auto/GPS mode, fresh OBD-II vehicle speed can briefly extrapolate a recent GPS fix when a reliable GPS course is available; in Radio mode, fresh speed can increase local radio scan cadence while moving. OBD-II is optional and has no separate positioning mode. Standard PID support is discovered per vehicle when possible; unsupported readings fall back independently. BLE/USB transports are not yet supported.
- **Risk-zone management:** draw multiple named polygons, rename/delete them and enable/disable each zone.
- **Continuous fix control and system delivery:** the main “Enable fix” button starts/stops the foreground location service and mock output. Calculated fixes are sent to Android's system fused provider and, when Google Play services is available, to Fused Location Provider clients. In GPS/Auto modes the physical GPS provider is kept intact so Clear GPS can continue filtering real GNSS input; direct clients explicitly requesting GPS may therefore still read the physical fix. Radio-only mode can replace GPS and network providers because it does not consume them as inputs. Android marks these locations as mock, and some apps deliberately ignore them. The refresh interval is configurable from 1 to 30 seconds; radio scans remain subject to Android throttling. Recording observations is still a separate switch.
- **Guarded fallback:** previously recorded radio estimates are considered only when recent, matched against enough local points and within a conservative accuracy threshold. A manual reference can be enabled as a final, coarse fallback. Cached scans do not refresh the last-confirmed mock-fix timer; if fresh publication stops, the service removes the stale mock provider after a bounded 30–90 second watchdog window. Diagnostic messages distinguish heard radios, identifiers found in the database, and entries with usable coordinates.
- **Storage and map limits:** up to 20,000 detailed observations and 500 scan-history entries are retained; the map renders up to 1,500 saved points on ordinary devices and lowers the limit on low-RAM devices.
- **Memory-aware Windows build:** Gradle heap is sized from installed/free RAM with a safety reserve for Windows; the daemon, parallel execution and build cache are enabled.
- **Fix cadence:** configurable interval from 1 to 30 seconds. With adaptive updates enabled, the interval can be halved during faster movement. Android may throttle actual Wi-Fi/Bluetooth scans.
- **Private map fallback:** a tile-free offline canvas retains local radio markers without requesting map data, but does not display streets or labels.
- **Windows build script** and GitHub Actions workflow for unit tests and debug APK generation.

## Radio positioning and WiGLE

WiGLE is supported as a **local file interchange format**, not as a remote database dependency. Import a CSV (plain or gzip) or a SQLite database exported by WiGLE; the importer recognises the `network` summary and `location` observation tables. SQLite imports are validated and merged into the current database rather than replacing it. The export menu offers three distinct outputs: WiGLE CSV (one row per retained observation, plus a representative row for a radio with no history), a WiGLE-shaped SQLite database (`network` and geolocated `location` rows), and a full Clear GPS SQLite backup (radio summaries, observation history, and scan history). WiGLE-shaped exports omit unlocated observations because the WiGLE `location` format requires coordinates; use the full Clear GPS backup to preserve all app history. Identifiers are normalized to lowercase and duplicate observations are skipped when the same file is imported again. Clear GPS never asks for a WiGLE username/API key and never uploads selected files.

A Wi-Fi/Bluetooth identifier by itself does not reveal coordinates. For radio-only navigation, first record scans at places with known coordinates, use a manual reference as coarse training data, or import a compatible WiGLE CSV. Clear GPS now prioritizes **radio fingerprint matching**: it compares current identifiers and RSSI values with complete, previously recorded local scans, weights similarity by radio type and signal-level differences, and combines nearby high-quality matches. If no suitable scan fingerprint exists, it falls back to the geolocated radio-point table using capped per-radio-type weights, a deliberately softened RSSI influence, and spatial outlier rejection. If nearly identical fingerprints point to distant places, the algorithm refuses to choose one. Radio-only estimates are never written back as ground-truth training coordinates, avoiding self-reinforcing drift. For non-manually-edited, non-WiGLE points, a new strongest RSSI sample can still refine the stored approximate reception location when its reference fix is no worse than 50 m; this does not triangulate an antenna or guarantee transmitter coordinates. Estimates remain heuristic and require previously geolocated recordings; moved access points, changing radio conditions, or sparse coverage can still cause a missing or wrong fix. Cell identifiers are collected only when Android exposes them and do not become coordinates without local reference data.

## Read-only OBD-II foundation

OBD-II connects only after the user opens the OBD-II screen, selects a previously paired Bluetooth Classic SPP adapter and taps Connect. It does not start Bluetooth discovery. Android's Nearby devices / `BLUETOOTH_CONNECT` permission is used only to list paired adapters and connect to the selected adapter.

The client first requests standard SAE J1979 Mode 01 PID 00 (the read-only support bitmap for PIDs 01–20), then reads only PID 0D (vehicle speed). If the bitmap is absent or unusable, it probes PID 0D only; if the ECU reports it unsupported, the PID is skipped. RPM, coolant temperature and unrelated diagnostic values are not requested. An invalid or unavailable speed sample is discarded, and the selected GPS/radio positioning source continues without OBD-II assistance. The screen shows a red status explaining the failure and fallback. The fixed allowlist rejects arbitrary requests. `ATE0`, `ATL0`, `ATS0`, `ATH0`, `ATAT1` and `ATSP0` configure only the ELM-compatible adapter's output, adaptive timing and automatic protocol selection; no ECU reset, trouble-code clearing, coding, adaptation or write service is sent.

Only fresh PID 0D speed contributes to position fallback. When Auto/GPS mode is selected and a connected OBD-II adapter provides fresh speed, the **map** can extrapolate for at most 30 seconds from a recent GPS fix, only when that fix has a course, reported GPS accuracy is at most 100 metres, and speed data is no more than 5 seconds old; projected travel is capped at 300 metres and estimated uncertainty grows with time and distance. If those conditions fail, the map reverts to the current GPS fix or stops presenting it as fresh rather than guessing a direction. When the foreground monitor is running, it can also publish that bounded prediction through the mock GPS provider **only if mock-location output was explicitly enabled**, the last fix was accepted as NORMAL by the GNSS filter, and the position is outside risk zones. The prediction is not fed back to the spoofing detector; an alert, stale input, excessive projected distance or a new source mode stops and clears it. When Radio mode is selected, the local radio database remains the only coordinate source and fresh OBD speed may shorten radio scan intervals while moving. Vehicle speed alone cannot determine a position. The latest speed sample is handed between the app and foreground service through a timestamped preference and is considered usable for only 5 seconds; it is not a trip history and is cleared on disconnect. Initial transport support is Bluetooth Classic RFCOMM/SPP; BLE and USB require separate transports.

## Privacy and network traffic

- **BeaconDB is opt-in and disabled by default.** Only a manual cell-only query can call `https://api.beacondb.net/v1/geolocate`; the contribution endpoint is never used. No WiGLE API requests run and no network lookup starts in the background.
- **No automatic upload.** Scans, labels, coordinates, zones and history are stored locally in app-private SQLite/preferences.
- **Local radio identifiers.** SSIDs and BSSIDs are stored in the private local database for search and editing. Bluetooth device names and advertisement payloads are not read or stored. SSIDs, BSSIDs, cell IDs and BLE addresses are never added to map requests or uploaded by Clear GPS.
- **Maps are still online by default.** OpenFreeMap serves map styles/tiles from its public service, so ordinary map requests expose the device's IP address and which map area is being viewed to that map provider. Wireless identifiers are not attached to those requests. For more private use, the map component must be pointed at a self-hosted or offline map source.
- **Permissions matter.** Android can throttle Wi-Fi scans, limit cell information, randomize Bluetooth addresses, and refuse scans when permissions or system settings do not allow them. Turning off global Android location can also block Wi-Fi scanning on some versions/devices.
- **Radio-only is an app-level mode.** A regular Android application cannot force the system-wide GNSS hardware switch off without privileged/system access. Clear GPS can stop requesting GPS updates itself; supplying locations to other apps additionally requires selecting Clear GPS as the mock-location app in Developer options. Some apps detect or ignore mock locations.
- The app is experimental and does not guarantee accurate navigation or detect every kind of GNSS spoofing.

## Build on Windows

Run **build-apk.bat** from the repository root. The helper checks for a compatible Java/Android SDK/Gradle setup and can offer to install missing tools after confirmation. It verifies downloaded archive hashes when supported by the bootstrap script.

After a successful build, the APK is written to **dist/ClearGPS-debug.apk**. You can also download the **ClearGPS-debug** artifact from the [GitHub Actions runs](https://github.com/MAKAKAIglitch/clear-gps/actions).

## Maps and attribution

The default map styles are supplied by [OpenFreeMap](https://openfreemap.org/) and use OpenMapTiles / OpenStreetMap data. Attribution is shown in the app. OpenFreeMap's public styles are convenient but require internet access; consult its current [terms](https://openfreemap.org/tos/) before adding offline downloads or larger-scale caching. No map tiles are bundled in the APK.

## Development status

This is a research/learning project. The app has automated build and unit-test checks, but the full scan/record/edit/radio-only workflow still needs hands-on validation on real Android devices and different manufacturers. The stated accuracy radius of a local estimate is heuristic rather than a surveyed guarantee.

# Русский

**Clear GPS — экспериментальное Android-приложение для локальной записи Wi-Fi/Bluetooth/сотовых радиоточек, навигации по собственной базе и фильтрации GNSS-аномалий.**

Проект построен на Kotlin, Jetpack Compose, Material 3 и MapLibre Native. Радиоидентификаторы сканируются только по команде пользователя или при явно включённой записи. Наблюдения остаются в приватной SQLite-базе приложения. Запросы BeaconDB **выключены по умолчанию**. Если пользователь отдельно разрешит их в настройках и нажмёт кнопку поиска, приложение отправит только поддерживаемые ID текущих сотовых ячеек и уровни сигнала в геолокационный API BeaconDB. Wi-Fi, Bluetooth, GPS-координаты и вклад наблюдениями не отправляются; endpoint отправки вкладов не вызывается. API WiGLE не используется.

## Возможности

- **Интерфейс в духе Pixel / Material 3:** динамические цвета Android 12+, темы карты «система / светлая / тёмная», понятные статусы сканирования.
- **Карта MapLibre** на основе OpenFreeMap и данных OpenStreetMap: тёмная и светлая темы, синяя точка позиции с радиусом точности, янтарный ручной ориентир, цветные радио-точки и несколько именованных зон риска.
- **Локальный сканер:** Wi-Fi BSSID/уровень сигнала/частота, доступные Android идентификаторы сотовых сот GSM/WCDMA/LTE/NR, адреса и RSSI Bluetooth LE.
- **Локальная SQLite-база и выбор источника:** по умолчанию открывается локальная база; сверху вкладки «База» можно переключить просмотр на BeaconDB. BeaconDB-доступ ограничен ручным поиском по сотовым ячейкам: он показывает оценку координат и ячейки, использованные в запросе, но не список записей сервера.
- **Режим «Только радио»:** Clear GPS перестаёт запрашивать системные провайдеры геолокации и рассчитывает положение только при совпадении текущих радиосигналов с координатными точками локальной базы. Режим не выключает GNSS-модуль для всей системы Android.
- **Обмен с WiGLE:** импорт CSV (обычный или gzip), WiGLE SQLite (`network` / `location`) и резервных копий Clear GPS; экспорт CSV по отдельным наблюдениям, WiGLE-совместимой SQLite и полной SQLite-копии Clear GPS. Импорт объединяет данные и не дублирует уже имеющиеся наблюдения.
- **Основа OBD-II только для чтения:** подключение по запросу к уже сопряжённому Bluetooth Classic SPP адаптеру; для позиционирования читается только стандартный PID скорости автомобиля 0D и карта поддержки PID 00. Обороты, температура и другие диагностические параметры не запрашиваются. BLE/USB и фирменные автомобильные интерфейсы пока не поддерживаются.
- **Зоны спуфинга:** рисование нескольких полигонов, переименование, удаление и отдельное включение каждой зоны.
- **Кнопка фикса и передача в приложения:** «Включить фикс» запускает foreground-сервис и публикацию рассчитанных координат через системный fused-провайдер Android и Google Fused Location Provider (если доступны Google Play services); отдельный статус показывает результат этой передачи. В режимах «GPS» и «Авто» настоящий GPS-провайдер не подменяется, иначе приложение перестало бы получать новые физические GNSS-фиксы для фильтрации. Поэтому приложения, которые напрямую запрашивают именно GPS-провайдер, могут по-прежнему видеть исходный GPS; приложения, использующие fused location, получают вычисленную позицию. В режиме «Только радио» можно дополнительно подменять GPS и network-провайдеры, поскольку они не используются как входы. Android помечает такие позиции как mock, и некоторые приложения намеренно их игнорируют. Интервал обновления настраивается от 1 до 30 секунд. В режиме GPS радиосканирование, запись и отображение радио-точек отключены; GNSS-фильтр работает независимо от локальной радиобазы.
- **Диагностика mock location:** настройки показывают, включён ли запрос фикса и подтвердил ли Android публикацию тестового провайдера. Для передачи координат нужно выбрать Clear GPS как приложение фиктивного местоположения в настройках разработчика. В режиме «Только радио» локальная оценка публикуется через GPS- и сетевой mock-провайдеры, чтобы её получали приложения, запрашивающие любой из этих источников; в GPS/«Авто» сетевой провайдер не подменяется, чтобы сохранить системный источник фильтра. Отдельная кнопка в просмотре BeaconDB позволяет вручную опубликовать готовую cell-only оценку через оба mock-провайдера на 2 минуты; повторных запросов BeaconDB она не делает, а радиус погрешности увеличивается по времени. Android помечает такие координаты как mock, и отдельные приложения могут их игнорировать.
- **Журнал ошибок:** в настройках → «Прочее и диагностика» можно включить подробные локальные журналы, ограничить размер от 64 до 512 КБ, открыть журнал, очистить его или скопировать актуальный текст целиком. Логирование выключено по умолчанию; журнал не содержит MAC/BSSID и точных координат, но может содержать диагностические статусы и причины ошибок.
- **Ограничение объёма данных:** до 20 000 подробных наблюдений и 500 записей истории; на карте одновременно показывается не более 400 сохранённых радио-точек.
- **Сборка с учётом ОЗУ:** heap Gradle рассчитывается по доступной/установленной памяти с резервом для Windows; включены daemon, параллельная сборка и кэш.
- **Частота фикса:** интервал 1–30 секунд; при включённой адаптации интервал может уменьшаться в движении. Фактическая частота радиообновлений зависит от системных ограничений Android. Кэшированные сканы не продлевают таймер последнего подтверждённого mock-фикса; если свежая публикация прекратилась, watchdog удаляет устаревший mock-провайдер через ограниченное окно 30–90 секунд. Диагностика отдельно показывает услышанные радиосигналы, найденные в базе идентификаторы и записи с пригодными координатами.
- **Приватный режим карты:** офлайн-холст не запрашивает тайлы, но показывает локальные радиоточки без улиц и подписей.
- **Сборка для Windows** и GitHub Actions для тестов и создания debug APK.

## Локальная навигация и WiGLE

WiGLE поддерживается как **локальный файловый формат**, а не как удалённый сервис. BeaconDB не предоставляет публичный полный дамп для скачивания: её публичный API возвращает оценку местоположения по предоставленным данным ячеек, а не каталог всех записей. Поэтому вкладка BeaconDB — это отдельный ручной cell-only поиск, не синхронизация и не импорт серверной базы. Можно импортировать CSV (обычный или gzip) либо SQLite-базу WiGLE; распознаются таблицы `network` (сводка сетей) и `location` (отдельные наблюдения). Импорт SQLite проверяется и объединяется с текущей базой, а не заменяет её. Меню экспорта предлагает три разных файла: WiGLE CSV (строка на каждое сохранённое наблюдение и одна сводная строка для точки без истории), WiGLE-совместимую SQLite с таблицами `network` и `location`, а также полную резервную копию Clear GPS SQLite с радиоточками, историей наблюдений и историей сканирований. В WiGLE-форматы не включаются наблюдения без координат, поскольку формат таблицы `location` требует координаты; для сохранения всей истории приложения используй полную резервную копию Clear GPS. Идентификаторы приводятся к нижнему регистру, повторный импорт того же файла не должен добавлять одинаковые наблюдения. Clear GPS не запрашивает WiGLE API key и не отправляет выбранные файлы на сервер.

Один Wi-Fi/Bluetooth идентификатор сам по себе не даёт координат. Для радионавигации сначала запиши сканирования в местах с известным положением, используй ручной ориентир как грубую учебную точку или импортируй совместимый WiGLE CSV. Clear GPS в первую очередь применяет **сопоставление радиоснимков**: сравнивает текущие идентификаторы и RSSI с полными сканированиями из локальной базы, учитывает тип радио и различия уровня сигнала, затем объединяет близкие качественные совпадения. Если подходящего отпечатка нет, используется запасной расчёт по координатам радиоточек с ограничением влияния каждого типа радио, ослабленным влиянием RSSI и отбрасыванием пространственных выбросов. Если почти одинаковый отпечаток найден в удалённых местах, алгоритм отказывается угадывать. Результат режима «Только радио» не записывается обратно как достоверная учебная координата — это предотвращает накопление ошибки от самоподкрепления. Для точек, которые не закреплены вручную и не импортированы из WiGLE, новый максимум RSSI всё ещё может уточнить примерное место приёма, если исходный ориентир имеет точность не хуже 50 м; это не триангуляция и не гарантия координат антенны. Расчёт остаётся эвристическим и требует ранее записанных сканирований с координатами. Перестановка точек доступа, изменение радиосреды или малое число совпадений могут привести к отсутствию позиции или ошибке. Для запасного расчёта координатные Wi-Fi/сотовые записи могут использоваться до 5 лет, а BLE — до 180 дней; возраст добавляет штраф к погрешности, поэтому старые записи не считаются столь же надёжными, как свежие. Сканирования ячеек сотовой сети старше 5 минут отбрасываются по метке времени. Идентификаторы сотовых сот доступны только когда их предоставляет Android; без локальных координат они не превращаются в геолокацию автоматически.

## Основа OBD-II только для чтения

OBD-II запускается только по действию пользователя: открыть вкладку, выбрать ранее сопряжённый Bluetooth Classic SPP-адаптер и нажать «Подключить». Поиск окружающих Bluetooth-устройств не выполняется. Разрешение Android «Устройства поблизости» / `BLUETOOTH_CONNECT` используется только для списка сопряжённых адаптеров и подключения к выбранному.

Сначала приложение запрашивает стандартный SAE J1979 Mode 01 PID 00 — битовую карту поддержки PID 01–20, затем читает только PID 0D (скорость автомобиля). Если битовая карта отсутствует или некорректна, приложение пробует только PID 0D; если ЭБУ сообщает, что PID не поддерживается, запрос пропускается. Обороты, температура и другие диагностические значения не запрашиваются. При отсутствии или недостоверности скорости старое значение очищается, а выбранный GPS/радио источник продолжает позиционирование без OBD-II. Красная плашка объясняет причину и выбранный резервный вариант. Список команд ограничен: произвольные запросы не принимаются. Команды `ATE0`, `ATL0`, `ATS0`, `ATH0`, `ATAT1` и `ATSP0` меняют только текстовый вывод, адаптивное ожидание и автоматический выбор протокола на ELM-совместимом адаптере. Запись в ЭБУ, сброс ошибок, кодирование и адаптации не выполняются.

Для резервной геолокации используется только свежая скорость PID 0D. В режимах «Авто» и «GPS» подключённый OBD-II с актуальной скоростью позволяет **карте** кратковременно продолжить последнюю GPS-оценку максимум на 30 секунд — только если у фикса есть курс, заявленная GPS-точность не хуже 100 метров, а значение скорости не старше 5 секунд; расчётное перемещение ограничено 300 метрами, а оценка погрешности растёт со временем и расстоянием. Если условия не выполнены, карта возвращается к обычному GPS-фиксу либо прекращает показывать его как свежий, а не угадывает направление. Когда foreground-монитор запущен, он также может передавать этот ограниченный прогноз через фиктивный GPS-провайдер, **только если пользователь отдельно включил фиктивную геолокацию**, последний GPS-фикс принят GNSS-фильтром как NORMAL, а координата вне зон риска. Прогноз не подаётся обратно на вход фильтра; тревога, устаревание датчиков, превышение лимита расстояния или смена режима останавливает и очищает его. В режиме «Только радио» единственным источником координат остаётся локальная радиобаза, а свежая скорость может учащать её сканирование в движении. Одна скорость сама по себе не определяет координаты. Последняя скорость кратковременно передаётся между приложением и foreground-сервисом через preference с меткой времени и считается пригодной только 5 секунд; это не история поездок, при отключении она очищается. Сейчас поддерживается Bluetooth Classic RFCOMM/SPP; для BLE и USB нужен отдельный транспорт.

## Приватность и сетевые запросы

- **BeaconDB — только по явному разрешению.** По умолчанию сетевые запросы выключены. При включении вручную отправляются только поддерживаемые ID текущих сотовых ячеек и уровни сигнала на `https://api.beacondb.net/v1/geolocate`; IP-адрес также виден серверу как обычному HTTPS-соединению. Wi-Fi, Bluetooth и GPS-координаты в запрос не входят. API отправки вкладов `v2/geosubmit` не вызывается. Сетевой поиск не запускается автоматически.
- **Нет автоматической загрузки.** Сканирования, подписи, координаты, зоны и история хранятся в приватных SQLite/preferences на устройстве.
- **Локальные радиоданные.** SSID, BSSID, сотовые ID и BLE-адреса остаются в локальной базе. Имена Bluetooth и содержимое BLE-рекламы не читаются. При выключенном BeaconDB-переключателе сотовые ID никуда не отправляются. При разрешённом ручном cell-only запросе BeaconDB получает только поддерживаемые ID текущих сотовых ячеек и уровни сигнала; SSID/BSSID, BLE-адреса, GPS-координаты и история наблюдений не отправляются.
- **Карта по умолчанию всё ещё онлайн.** OpenFreeMap отдаёт стили и тайлы с публичного сервиса, поэтому его сервер видит обычный IP-адрес устройства и запрашиваемые участки карты. Радиоидентификаторы к картографическим запросам не добавляются. Для более приватного режима нужно подключить собственный сервер или локальную карту.
- **Ограничения Android остаются.** Система может ограничивать частоту Wi-Fi-сканирования, скрывать часть информации о сотах и использовать рандомизированные Bluetooth-адреса. Clear GPS ограничивает повторный запрос Wi-Fi-скана примерно одним разом в 30 секунд, даже если mock-fix выставлен на 1 секунду: это снижает риск системного троттлинга. При пропуске одного радиосканирования последнее подтверждённое mock-положение можно удерживать только ограниченное время с растущей погрешностью; старые кэшированные данные не продлевают таймер бесконечно. На некоторых версиях/устройствах выключение глобальной геолокации блокирует и Wi-Fi-сканирование.
- **«Только радио» — режим самого приложения.** Обычное Android-приложение не может принудительно выключить GNSS-модуль для всей системы без системных привилегий. Clear GPS может перестать запрашивать GPS-провайдер; передача координат другим приложениям дополнительно требует выбора Clear GPS как приложения фиктивной геолокации в настройках разработчика. Некоторые приложения распознают или игнорируют фиктивные координаты.
- Проект экспериментальный и не гарантирует точность навигации или обнаружение всех вариантов GNSS-спуфинга.

## Сборка на Windows

Запусти **build-apk.bat** из корня репозитория. Сборщик проверяет Java, Android SDK и Gradle; при необходимости он предлагает установить недостающие инструменты после подтверждения. Где доступно, скачиваемые архивы проверяются по хешам.

После успешной сборки APK будет в **dist/ClearGPS-debug.apk**. Также его можно получить как артефакт в [GitHub Actions](https://github.com/MAKAKAIglitch/clear-gps/actions).

## Карты и атрибуция

По умолчанию используются стили [OpenFreeMap](https://openfreemap.org/) на основе OpenMapTiles / OpenStreetMap. Атрибуция показывается в приложении. Публичные стили OpenFreeMap удобны, но требуют интернет; перед реализацией офлайн-загрузки или более крупного кэширования изучи актуальные [условия сервиса](https://openfreemap.org/tos/). Карты не включены в APK.

## Статус разработки

Это исследовательский проект. Сборка и unit-тесты автоматизированы, но полный сценарий сканирования/записи/редактирования/радионавигации ещё нужно проверять на реальных телефонах Android разных производителей. Указанный радиус точности локальной оценки — эвристика, а не измеренная гарантия.
