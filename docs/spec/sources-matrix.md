# Матрица источников позиции и доверия

Статус: спецификация Этапа 0. Источники независимы по жизненному циклу: сбой одного отключает только его. Источник без пригодных данных не должен заставлять приложение угадывать координату.

| Источник | Роль | Ограничения и обработка |
|---|---|---|
| Сырые GNSS `Gnss*` | Основная спутниковая оценка и вход детектора | Детектору передаются сырые измерения, не системный `Location`; отсутствующие raw-поля нейтральны |
| Android network-location | Независимая кросс-проверка, только если она не является собственной mock-оценкой | Нельзя передавать её напрямую как сырые GNSS-данные; происхождение и время должны быть известны |
| Локальные Wi-Fi-точки и fingerprints | Позиционирование по совпадениям с ранее записанными координатными наблюдениями | RSSI зависит от устройства и среды; мобильные/перемещаемые точки фильтруются; без достаточных совпадений позиция не объявляется достоверной |
| Сотовые ячейки | Грубый якорь и независимая кросс-проверка | Идентификаторы доступны не на всех устройствах; соты сами по себе не дают точных координат; координаты сетевой базы требуют метаданных происхождения |
| BLE-маяки | Дополнительная радиопозиция по стабильным маякам | Случайные адреса отбрасываются; используются стабильные iBeacon/Eddystone-маяки |
| IMU телефона | Счисление пути и проверка физической согласованности | Добавлен 10 Гц diagnostic-only reader: `TYPE_LINEAR_ACCELERATION` переводится в восток/север по свежему `TYPE_ROTATION_VECTOR`; хранится только последняя выборка в памяти (TTL 500 мс). Без пары свежих датчиков результат отсутствует. В позиционный fusion и TrustEngine пока не передаётся; ошибка интегрирования ещё не оценивается |
| OBD-II | Скорость/движение, проверка согласованности и помощь счислению пути | Сама скорость не задаёт координаты; PID и транспорт могут отсутствовать; ошибки не должны рушить позицию |
| Барометр | Относительные изменения высоты и кросс-проверка | Android `TYPE_PRESSURE` считывается во время активного мониторинга с монотонной меткой времени; последнее давление хранится только в памяти и считается свежим до 5 с. Разрешение сенсора не подменяет погрешность. Автокалибровка/температурная модель и передача в TrustEngine не подключены; погодный дрейф требует контроля |
| DEM (SRTM/Copernicus GLO-30) | Офлайн-источник рельефа и диагностика высоты | Добавлены reader локальных SRTM HGT 1/3 arc-second, импорт ZIP-пакета и ограниченная по частоте диагностическая выборка после доверенного NORMAL GPS-фикса. Результат показывает datum EGM96; координата не хранится, отсутствие тайла/void нейтрально. Сравнение с GNSS/barometer, Copernicus GLO-30 и live TrustEngine/fusion ещё не реализованы |
| BeaconDB | Дополнительная радиооценка онлайн-геолокации | Ручной запрос требует отдельного согласия. В запрос входят доступные Wi-Fi BSSID/RSSI, стабильные BLE MAC/RSSI и поддерживаемые GSM/WCDMA/LTE ID/RSSI; SSID, имена/payload Bluetooth, GPS-координаты и история не передаются. Обычные сканы не обращаются к сети: если переключатель BeaconDB включён для позиционирования, используется только свежий (до 2 минут) кэш с RSSI-группировкой по 10 dBm. Результат не записывается в локальные fingerprints. Вес источника в объединённой оценке — 0,85; отдельное разрешение сетевых запросов остаётся выключенным по умолчанию |
| OpenCellID | Дополнительный грубый cell-position источник по локальному каталогу | Личный API-ключ и отдельное разрешение; только ручной поиск. Передаются текущие MCC/MNC/LAC или TAC/full Cell ID и ключ, без RSSI, Wi-Fi/BSSID, BLE, GPS и истории. Результат `/cell/get` — расчётное положение записи сотовой ячейки по наблюдениям сообщества, не координата телефона и не обязательно физическое место антенны. Кэш хранится отдельно: найдено 30 дней, не найдено 7 дней; для позиционирования запись может использоваться до 90 дней с ростом погрешности и минимумом 5 км. В обычных сканах сетевых запросов нет. Один пакет — до 3 новых ячеек с паузой 15 минут; предел Clear GPS — 100 попыток за UTC-день, при официальной квоте сервиса до 1 000 кредитов в сутки на пользователя. Вес источника — 0,30. Атрибуция CC BY-SA 4.0 обязательна |
| Ручной ориентир | Грубый запасной вариант | Только явное включение; видимый статус «грубый запасной»; не скрывает отсутствие достоверных сенсорных данных |

## Приоритет и конфликт

Текущая реализация содержит два разных уровня: радиоисточники объединяются в `RadioPositionFusion` внутри приложения, а GNSS/IMU/OBD fusion и TrustEngine остаются отдельными направлениями проекта. Радиоисточники взвешиваются по обратной дисперсии точности с дополнительным доверием к источнику. При сильном расхождении выбирается источник с наибольшим эффективным весом, оценка точности увеличивается и конфликт показывается в статусе; приложение не выдаёт среднюю точку между далёкими несовместимыми оценками.

Сейчас локальная SQLite-оценка имеет вес 1,00, BeaconDB cache — 0,85, OpenCellID cache — 0,30. Вклад OpenCellID ограничен минимумом 5 км точности, учитывает заявленный диапазон ячейки, число наблюдений, RSSI и возраст записи; устаревшие более 90 дней записи из позиционирования исключаются. Это не является измеренным handset fix. Переключатели источников находятся в «База → Источники объединённой позиции»; они управляют только включением в расчёт, не удаляют кэш/историю и не включают сетевые запросы.

## BeaconDB: граница текущего контракта

Текущий ручной запрос соответствует фактическому `BeaconDbClient.kt` / `BeaconDbProtocol.kt`: отправляются доступные Wi-Fi BSSID/RSSI, стабильные BLE MAC/RSSI и поддерживаемые GSM/WCDMA/LTE cell IDs/RSSI. SSID, имена и payload Bluetooth, GPS-координаты и история сканирования не отправляются; API загрузки наблюдений не вызывается. BeaconDB-запрос выключен по умолчанию и требует отдельного разрешения плюс ручного нажатия кнопки. Кэш хранится только в памяти процесса до 2 минут, RSSI группируется по 10 dBm, чтобы небольшие колебания сигнала не вызывали повторный сетевой запрос. Обычные radio scans используют только кэш, без сетевых вызовов. NR/5G в BeaconDB не отправляется, поскольку его текущий контракт/парсер не принимает этот тип ячейки.

## OpenCellID: граница текущего контракта

OpenCellID обращается только к read-only `/cell/get`, передавая личный API-ключ и MCC/MNC/LAC или TAC/full Cell ID текущей ячейки; RSSI, Wi-Fi/BSSID, BLE, GPS и история не передаются. Запросы выполняются только вручную. Каждый запуск обрабатывает не более трёх новых ячеек, пакеты разделяются паузой не менее 15 минут; локальный предел Clear GPS — 100 попыток на UTC-день при стандартной квоте сервиса до 1 000 API-кредитов на пользователя в сутки. Результаты «найдено» кэшируются 30 дней, «не найдено» — 7 дней; временные, авторизационные и квотные ошибки не записываются как отсутствие ячейки. Рутинное позиционирование читает отдельный SQLite-кэш, а не сеть.
