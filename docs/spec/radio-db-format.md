# Формат радиобазы Clear GPS

Статус: спецификация Этапа 0. Схема должна допускать будущие типы источников без перестройки базовых сущностей.

## 1. Разделение данных

Храним отдельно:

1. **Источник** — откуда импортирована или получена запись.
2. **Радиоточкa** — известный идентификатор радио и необязательные координаты.
3. **Наблюдение** — факт обнаружения радио в конкретный момент, с уровнем сигнала и метаданными.
4. **Оценка координат** — вычисленный результат позиционирования; сама по себе не является эталонной записью радиобазы.

Виды источников локальной радиобазы: `local`, `wigle`, `beacondb`, `custom`; их отдельные наборы можно включать/исключать и перенастраивать доверие. BeaconDB не записывает наблюдения в SQLite: её краткоживущий кэш остаётся в памяти и участвует в расчёте позиции только при явном включении источника. OpenCellID хранится отдельным каталогом `opencellid_cells` с идентификатором ячейки, примерными координатами, радиусом, числом измерений, признаком проверки и статусом. Эти записи не смешиваются с таблицами `radio_points`/`radio_observations` и не становятся ground truth. Однако актуальные записи каталога могут участвовать как независимая грубая оценка в уровне расчёта позиции через source fusion; они сохраняют происхождение `opencellid` и консервативную погрешность.

## 2. Поля записи радиоточki

Минимальные смысловые поля:

- тип радио: Wi-Fi, сотовая ячейка или BLE;
- нормализованный идентификатор, если он доступен;
- координаты WGS84, если координаты известны; неизвестные координаты остаются неизвестными, а не превращаются в (0, 0);
- источник и происхождение координат;
- дата последнего наблюдения и число доступных наблюдений;
- оценка доверия / качества и сведения о точности координаты, если они действительно известны;
- необязательные типоспецифичные поля: частота, канал, PCI/TAC и доступные идентификаторы сотовой сети;
- версия схемы и место для неизвестных дополнительных полей.

У записи должна быть возможность явно различить измеренную или вручную подтверждённую точку и координаты, полученные из сетевой базы. Координаты сторонней базы не считаются измеренными координатами антенны.

## 3. Наблюдения

Наблюдение содержит идентификатор записи/источника, тип радио, время, RSSI и доступные частоту/канал/сотовые параметры. Если координата наблюдения известна, сохраняются координата и свойства использованного позиционного fix; неизвестные сведения не синтезируются.

Временные метки сравнимы через монотонное время внутри сессии. Для долговременного хранения дополнительно применяется UTC-время.

## 4. Слияние и дубликаты

- Повторный импорт того же источника не должен создавать одинаковые наблюдения повторно.
- Идентификаторы нормализуются одинаково во всех путях импорта.
- Записи с одинаковым радио-ID, но разным происхождением нельзя безусловно сворачивать в одну «истинную» координату.
- При конфликтующих координатах сохраняется происхождение каждой стороны; разрешение конфликта выполняется логикой качества/сопоставления, а не правилом «последняя запись побеждает».
- Радио-оценка, полученная алгоритмом позиционирования, не записывается обратно как эталонная координата: нельзя допускать самоподкрепляющийся дрейф.
- Импорт должен валидировать типы и диапазоны полей; ошибки одной записи не должны портить весь набор данных.

## 5. Удаление и совместимость

Источники и импортированные наборы управляются отдельно: просмотр по дню, отключение, удаление с каскадом и отменой, экспорт. Удаление источника не оставляет зависимые наблюдения без владельца.

Для формата экспорта и схемы БД обязателен номер версии. Миграции тестируются; неизвестные поля сохраняются там, где формат это допускает. Изменения формата не должны молча менять смысл существующих координат или уровня доверия.

## 6. Ограничения источников

WiGLE в версии 1.0 используется как локальный файловый импорт/экспорт, не как API. BeaconDB — отдельный read-only онлайн-источник, сетевые запросы выключены по умолчанию и запускаются вручную после согласия; она может вносить вклад в расчёт только через свежий локальный in-memory cache. OpenCellID — независимый read-only `/cell/get` lookup по личному ключу, запускается только вручную; обычное позиционирование использует только отдельный локальный cache SQLite и не делает сетевых вызовов. Для экономии квоты Clear GPS ограничивает себя 100 попытками на UTC-день, 3 новыми ячейками за пакет и 15-минутным интервалом; кэш успешных записей — 30 дней, отрицательных — 7 дней. Обе сетевые оценки имеют собственное происхождение и не превращаются в обучающие радио-наблюдения. Общий обмен базами между пользователями в 1.0 не входит.
