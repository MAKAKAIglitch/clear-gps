# Проверка Clear GPS на реальном устройстве

Статус: ручной чек-лист для проверки критериев из `docs/spec/quality-criteria.md`. Отметка в этом файле означает только выполнение конкретного пункта на указанном устройстве и версии сборки; прохождение unit-тестов не заменяет проверку Android.

## A. Запуск и изоляция экранов

- [ ] Приложение запускается после чистой установки.
- [ ] Экран OBD-II открывается без инициализации карты.
- [ ] Настройки открываются без инициализации карты.
- [ ] Отсутствие GMS не мешает доступным сценариям.
- [ ] Отсутствующие датчики показаны как недоступные, а не как признак спуфинга.
- [ ] RU/EN и системный язык при первом запуске соответствуют настройкам устройства.

## B. Публикация mock-location

Проверять отдельно для каждого режима. Для каждого прогона использовать второе тестовое приложение, читающее позицию через Android `LocationManager`; не считать видимую точку на карте доказательством публикации.

- [ ] GPS: опубликованная позиция доступна через системный провайдер, а сырые GNSS callback-и продолжают поступать в детектор.
- [ ] Радио: при достаточных локальных радиоданных опубликованная позиция действительно доступна через `LocationManager`.
- [ ] Радио без пригодных совпадений: приложение не выдумывает координаты и не выдаёт старую позицию за свежую.
- [ ] Авто: переключение источника не создаёт длительного зависания или публикации просроченного fix.
- [ ] Проверено поведение fused-провайдера при наличии GMS; отдельно записано, что доступно без GMS.
- [ ] При отключении собственного mock приложение прекращает публикацию согласно выбранному режиму.

## C. Доверие и GNSS

- [ ] В нормальной открытой местности статус стабилен и не дребезжит.
- [ ] При потере GNSS в помещении/под навесом/в туннеле отсутствие сигнала само по себе не объявляется доказанным спуфингом.
- [ ] При устаревшем GNSS fix статус и пригодность позиции обновляются, а не остаются бесконечно «нормальными».
- [ ] Если доступен AGC, экран диагностики показывает его доступность и корректно отображает данные.
- [ ] Отсутствие AGC или L5/E5 не увеличивает риск само по себе.
- [ ] Событие риска содержит объяснимые вклады сигналов; пользователь может поставить метку «ложная тревога» или «подтверждаю».
- [ ] Зоны риска проверены на вход, выход, границу и круг точности; повторные переходы не дребезжат.
- [ ] Геометрия проверена для вложенных отдельных зон, самопересекающегося полигона и полигона через антимеридиан (±180°).
- [ ] Проверено, что круг точности может пересечь край зоны без попадания центра, а грубая/некорректная точность не расширяет зону без ограничений.
- [ ] После входа зона удерживается до выхода за гистерезис 25 м; для нового входа запас выхода не применяется, а остановка мониторинга и отключение всех зон сбрасывают состояние.

Для проверки классификации атак использовать только синтетические сценарии и записанные реплеи. Не создавать радиопередачи для имитации спуфинга.

## D. Радио и локальная база

- [ ] При запрете разрешения сканирования GNSS/остальные доступные функции продолжают работать.
- [ ] Импорт поддерживаемого файла показывает количество записей и понятные ошибки некорректных строк.
- [ ] Повторный импорт не создаёт дубликаты там, где контракт источника допускает дедупликацию.
- [ ] Источник можно отключить, экспортировать и удалить; удаление зависимых записей соответствует предупреждению.
- [ ] Фильтр SSID действует и при записи, и при сопоставлении.
- [ ] Лимит подробных наблюдений применяется к локальной записи и после импорта.
- [ ] Резервная копия и восстановление настроек/зон проверены на тестовом наборе; импорт не включает mock, мониторинг, BeaconDB или replay самопроизвольно.
- [ ] BeaconDB выключен по умолчанию; перед запросом есть отдельное согласие; запрос содержит только предусмотренные cell-only поля; lookup не записывается автоматически в локальную радиобазу.

## E. OBD, датчики и сервис

- [ ] Сервис работает без OBD-адаптера.
- [ ] Отключение адаптера во время работы не завершает сервис.
- [ ] Неполный или некорректный ответ адаптера приводит к обработанной ошибке/таймауту, а не к падению.
- [ ] При отсутствии BLE/барометра/IMU приложение продолжает доступные сценарии.
- [ ] При включённом мониторинге проверены уведомление foreground-сервиса и остановка по команде пользователя.
- [ ] После принудительного завершения приложения и после перезагрузки проверено восстановление согласно сохранённому состоянию и Android-ограничениям.
- [ ] В debug-сборке StrictMode пишет найденные нарушения в Logcat и не завершает приложение из-за них.
- [ ] LeakCanary в debug-сборке проверен после многократного открытия/закрытия карты, OBD-II и настроек; нет воспроизводимых удерживаемых Activity/Service.
- [ ] Release runtime classpath / APK не содержит LeakCanary, а StrictMode-политика не включается в release.
- [ ] Длительный тест в движении/Doze выполнен; указать продолжительность, условия и все перерывы.

## F. Батарея, устойчивость и результаты

- [ ] Для Eco, Normal и Max измерен расход батареи в %/час в сопоставимых условиях.
- [ ] Записаны модель телефона, доступные датчики, версия Android, настройки и продолжительность теста.
- [ ] Для реплеев с известной разметкой рассчитаны precision, recall, ложные тревоги в час и задержка обнаружения.
- [ ] Результаты разделены по доступности AGC и двухчастотного GNSS, а также по контекстам среды.
- [ ] Ручной UI-чек-лист пройден минимум на трёх телефонах.
- [ ] Все найденные дефекты описаны с шагами воспроизведения; приватные координаты, SSID/BSSID и идентификаторы сот удалены из публикуемых логов.
