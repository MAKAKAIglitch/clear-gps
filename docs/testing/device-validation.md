# Проверка Clear GPS на реальном устройстве

Статус: ручной чек-лист для проверки критериев из `docs/spec/quality-criteria.md`. Отметка в этом файле означает только выполнение конкретного пункта на указанном устройстве и версии сборки; прохождение unit-тестов не заменяет проверку Android.

## A. Запуск и изоляция экранов

- [ ] Приложение запускается после чистой установки.
- [ ] Экран OBD-II открывается без инициализации карты.
- [ ] Настройки открываются без инициализации карты.
- [ ] Отсутствие GMS не мешает доступным сценариям.
- [ ] Отсутствующие датчики показаны как недоступные, а не как признак спуфинга.
- [ ] RU/EN и системный язык при первом запуске соответствуют настройкам устройства.
- [ ] В «Возможности устройства» корректно отображаются GPS-провайдер, свежесть raw GNSS, AGC, известные частотные диапазоны, барометр, Wi-Fi RTT и доступные IMU-датчики.
- [ ] При отключённом мониторинге экран не запускает GNSS, Wi-Fi/BLE-сканы, не запрашивает разрешения и показывает отсутствие свежих измерений как «неизвестно», а не как неисправность.
- [ ] При активном GPS/Авто повторное обновление отчёта отражает только свежие measurements/status, не сохраняя старые данные как текущие.
- [ ] На телефоне без Wi-Fi RTT и/или барометра остальные доступные сценарии продолжают работать без повышения риска из-за отсутствующего датчика.

## B. Публикация mock-location

Проверять отдельно для каждого режима. Для каждого прогона использовать второе тестовое приложение, читающее позицию через Android `LocationManager`; не считать видимую точку на карте доказательством публикации.

- [ ] GPS: опубликованная позиция доступна через системный провайдер, а сырые GNSS callback-и продолжают поступать в детектор.
- [ ] Радио: при достаточных локальных радиоданных опубликованная позиция действительно доступна через `LocationManager`.
- [ ] Радио без пригодных совпадений: приложение не выдумывает координаты и не выдаёт старую позицию за свежую.
- [ ] Авто: при устойчиво недоверенном GNSS / входе в зону после 10 с включается радио; при отсутствии первого GPS фикса действует период первичного захвата не менее 30 с (или два выбранных интервала обновления).
- [ ] Авто/радио: GPS проверяется каждые 120 с в окне не более 30 с, при этом радио продолжает выдавать позицию.
- [ ] Авто/радио: плохой GPS-фикс во время пробной проверки не отключает и не заменяет радио-позицию; возврат на GPS происходит только после нового физического фикса NORMAL вне активных зон.
- [ ] Авто: скачок радио-координаты сверх временно допустимого расстояния отклоняется; проверить плавность и отсутствие скачков на записанном тестовом треке.
- [ ] Проверено поведение fused-провайдера при наличии GMS; отдельно записано, что доступно без GMS.
- [ ] При отключении собственного mock приложение прекращает публикацию согласно выбранному режиму.

## C. Доверие и GNSS

- [ ] В нормальной открытой местности статус стабилен и не дребезжит.
- [ ] При потере GNSS в помещении/под навесом/в туннеле отсутствие сигнала само по себе не объявляется доказанным спуфингом.
- [ ] При устаревшем GNSS fix статус и пригодность позиции обновляются, а не остаются бесконечно «нормальными».
- [ ] Если доступен AGC, экран диагностики показывает его доступность и корректно отображает данные.
- [ ] Отсутствие AGC или L5/E5 не увеличивает риск само по себе.
- [ ] Событие риска содержит объяснимые вклады сигналов; пользователь может поставить метку «ложная тревога» или «подтверждаю».
- [ ] Зоны риска проверены на вход, выход, границу и круг точности; повторные переходы не дребезжат.
- [ ] Геометрия проверена для вложенных отдельных зон, самопересекающегося полигона и полигона через антимеридиан (±180°).
- [ ] Проверено, что круг точности может пересечь край зоны без попадания центра, а грубая/некорректная точность не расширяет зону без ограничений.
- [ ] После входа зона удерживается до выхода за гистерезис 25 м; для нового входа запас выхода не применяется, а остановка мониторинга и отключение всех зон сбрасывают состояние.

Для проверки классификации атак использовать только синтетические сценарии и записанные реплеи. Не создавать радиопередачи для имитации спуфинга.

## D. Радио и локальная база

- [ ] При запрете разрешения сканирования GNSS/остальные доступные функции продолжают работать.
- [ ] Импорт поддерживаемого файла показывает количество записей и понятные ошибки некорректных строк.
- [ ] Повторный импорт не создаёт дубликаты там, где контракт источника допускает дедупликацию.
- [ ] Источник можно отключить, экспортировать и удалить; удаление зависимых записей соответствует предупреждению.
- [ ] Фильтр SSID действует и при записи, и при сопоставлении.
- [ ] Лимит подробных наблюдений применяется к локальной записи и после импорта.
- [ ] Резервная копия и восстановление настроек/зон проверены на тестовом наборе; импорт не включает mock, мониторинг, BeaconDB или replay самопроизвольно.
- [ ] BeaconDB выключен по умолчанию; перед сетевым lookup требуется отдельное согласие. В запросе проверены только текущие поддерживаемые Wi-Fi BSSID/RSSI, публичные BLE MAC/RSSI (только допустимые public unicast адреса Android 15+) и поддерживаемые Cell ID/RSSI; SSID, Bluetooth names/payloads, GPS-координаты и история сканирования не отправляются.

## E. OBD, датчики и сервис
- [ ] При включении мониторинга IMU-диагностика появляется только при свежих `TYPE_LINEAR_ACCELERATION` + `TYPE_ROTATION_VECTOR`; при остановке службы выборка очищается и перестаёт считаться свежей.
- [ ] На устройстве без linear-acceleration или rotation-vector остальная работа продолжается; отсутствие IMU не повышает риск и не создаёт координату.
- [ ] При повороте/перекладывании телефона горизонтальные значения остаются только диагностикой; до отдельной полевой калибровки они не должны влиять на публикацию mock-position.

- [ ] Включить мониторинг с разрешением геолокации «Всегда», перезагрузить устройство и проверить восстановление только при сохранённом активном состоянии; проверить, что координаты до первого нового фикса не отображаются как свежие.
- [ ] Повторить с разрешением только «При использовании» и убедиться, что сервис не запускается в фоне, флаги активности сброшены и статус объясняет причину.
- [ ] При выключенном до перезагрузки мониторинге receiver не запускает сервис.

- [ ] Сервис работает без OBD-адаптера.
- [ ] Отключение адаптера во время работы не завершает сервис.
- [ ] Неполный или некорректный ответ адаптера приводит к обработанной ошибке/таймауту, а не к падению.
- [ ] При отсутствии BLE/барометра/IMU приложение продолжает доступные сценарии.
- [ ] При включённом мониторинге проверены уведомление foreground-сервиса и остановка по команде пользователя.
- [ ] После принудительного завершения приложения и после перезагрузки проверено восстановление согласно сохранённому состоянию и Android-ограничениям.
- [ ] После удаления задачи Clear GPS из списка недавних приложений foreground-сервис продолжает работу либо worker через 45 секунд обнаруживает отсутствие свежего heartbeat и пробует восстановление.
- [ ] При живом сервисе heartbeat обновляется каждые ~30 секунд; разовая проверка после `onTaskRemoved` не создаёт второй цикл и не очищает свежую позицию.
- [ ] При остановленном мониторинге watchdog не запускает сервис заново; проверить это после нажатия «Выключить фикс».
- [ ] При отзыве геолокации или отсутствии доступа «Всегда» worker оставляет понятный статус и не пытается бесконечно запускать location foreground service.
- [ ] Проверить поведение watchdog в Doze/на энергосбережении и записать фактическую задержку; расписание WorkManager не считается точным таймером.
- [ ] В настройках вручную запросить исключение из оптимизации батареи на Android 6.0+; проверить отображение системного запроса, возможность отказа и fallback на общий список/страницу приложения, если прямое окно недоступно.
- [ ] Проверить, что запрос исключения не открывается автоматически при старте и не удерживается постоянный wake lock.
- [ ] После отказа от исключения мониторинг продолжает работать в пределах системных ограничений, а ограничение не выдаётся за ошибку или гарантию отсутствия троттлинга.
- [ ] В debug-сборке StrictMode пишет найденные нарушения в Logcat и не завершает приложение из-за них.
- [ ] LeakCanary в debug-сборке проверен после многократного открытия/закрытия карты, OBD-II и настроек; нет воспроизводимых удерживаемых Activity/Service.
- [ ] Release runtime classpath / APK не содержит LeakCanary, а StrictMode-политика не включается в release.
- [ ] Длительный тест в движении/Doze выполнен; указать продолжительность, условия и все перерывы.

## F. Батарея, устойчивость и результаты

- [ ] После чистой установки энергосбережение необязательных фоновых задач включено по умолчанию, порог низкого заряда равен 20%; в настройках порог изменяется в диапазоне 5–50%.
- [ ] На батарее с включённым app saver выключение экрана приостанавливает автообновление внешних радиокаталогов, дополнительные радио-снимки replay и DEM-диагностику; после включения экрана они возобновляются при соблюдении остальных разрешений и интервалов, с повторной проверкой не позднее минуты.
- [ ] При уровне заряда на пороге или ниже необязательные фоновые задачи приостанавливаются и при включённом экране; проверить значения непосредственно выше, равные и ниже выбранного порога.
- [ ] При подключении питания необязательные задачи возобновляются; отдельно проверить, что включённый системный Battery Saver Android продолжает ограничивать необязательную работу.
- [ ] При выключенном app saver необязательная работа продолжается с выключенным экраном и низким зарядом, если системный Battery Saver не включён.
- [ ] При низком заряде и выключенном экране активный GPS/радиофикс, публикация включённого пользователем источника и сырые GNSS callback-и продолжают работать; PowerPolicy не должна отключать основной цикл позиционирования.
- [ ] Экспорт/импорт конфигурационной резервной копии v3 сохраняет переключатель и порог; импорт форматов v1/v2 подставляет включённый app saver и порог 20%.

- [ ] Для Eco, Normal и Max измерен расход батареи в %/час в сопоставимых условиях.
- [ ] Записаны модель телефона, доступные датчики, версия Android, настройки и продолжительность теста.
- [ ] Для реплеев с известной разметкой рассчитаны precision, recall, ложные тревоги в час и задержка обнаружения.
- [ ] Результаты разделены по доступности AGC и двухчастотного GNSS, а также по контекстам среды.
- [ ] Ручной UI-чек-лист пройден минимум на трёх телефонах.
- [ ] Все найденные дефекты описаны с шагами воспроизведения; приватные координаты, SSID/BSSID и идентификаторы сот удалены из публикуемых логов.

## G. Главная и отдельная карта

- [ ] При запуске открывается «Главная» без создания MapLibre MapView; положение, мониторинг, запись и GNSS-диагностика доступны как раньше.
- [ ] «Карта» — отдельная вкладка с MapView; переход «Главная → Карта → Главная» создаёт и освобождает MapView через один существующий lifecycle-путь.
- [ ] В «Базе», «Зонах», OBD-II и «Настройках» MapView не создаётся.
- [ ] В меню карты можно независимо скрывать/показывать Wi‑Fi, соты, BLE, центры позиции и погрешности, ручной ориентир, сохранённые зоны и справочные слои.
- [ ] Скрытие центров позиции также скрывает accuracy-круг во время его анимации; повторное включение восстанавливает последний актуальный центр и радиус.
- [ ] BeaconDB показывает только уже полученную оценку текущей сессии; включение/выключение слоя не выполняет запрос.
- [ ] OpenCellID показывает только локально сохранённые записи со статусом found, корректными координатами и возрастом не более установленного срока; пустой кэш не создаёт маркеры.
- [ ] Радиомаркер выбирается касанием в пределах квадратной области не менее 48 × 48 dp даже при неточном попадании по его центру.
- [ ] При пересечении областей касания выбирается ближайший маркер, а не первый в порядке слоёв.
- [ ] Совпадающие радиозаписи открывают лист «Что здесь»; выбор строки открывает подробности именно этой записи.
- [ ] Кластеры локальных радиоточек и OpenCellID раскрываются касанием; переключение видимости не меняет содержимое или доверие источников.
- [ ] Переключение online/offline подложки сохраняет прежнее поведение HTTPS OpenFreeMap / приватного пустого холста.
- [ ] Из «Главной» команда ручного ориентира открывает «Карту»; тап добавляет ориентир. Из «Зон» команда рисования открывает «Карту»; черновик, отмена и сохранение работают.
- [ ] После поворота экрана, ухода в фон и возврата нет двойных MapView callbacks, утечки слушателей или потери видимости слоёв.

## H. Радиоточка с наблюдениями и редактор зон (P1.3–P1.4)

- [ ] Открыть Wi‑Fi/BLE/сотовую точку: внешний вид и компоновка соответствуют Material 3 bottom sheet из 38edcc4 — исходные скругление, фон, заголовок, сведения, история и кнопки; сверху оставлено пустое место высотой бывшей ручки, сама ручка не рисуется.
- [ ] Немодальная карточка не затемняет и не блокирует свободную область карты; выбранная точка и фокус по строке истории располагаются внутри видимой области между шапкой и верхним краем карточки.
- [ ] Ручки перетаскивания нет; при касании и перемещении карты в свободной области карточка остаётся открытой, жест не сворачивает её; крестик закрывает карточку, прокрутка истории и кнопка «Редактировать» работают.
- [ ] Карточка сохраняет визуальное оформление Material 3 bottom sheet из 38edcc4, но является немодальной панелью без ручки перетаскивания и прозрачного полноэкранного перехвата касаний; открытая часть карты принимает жесты, максимальная высота оставляет видимую область карты.
- [ ] При открытии карточки камера показывает всю область валидных измерений выбранной точки в свободном viewport; верхний отступ считается от фактического положения MapView и нижнего края шапки в окне, нижний — до верхнего края карточки. Расчётный центр остаётся отдельным маркером.
- [ ] Открыть точку через «База» → «На карте» при доступной текущей геопозиции: после создания MapView камера должна показывать всю область валидных измерений выбранной радиоточки, а не центрироваться на текущем местоположении устройства.
- [ ] На карте нажать одиночный радиомаркер: карточка открывает эту точку, камера плавно масштабируется так, чтобы все валидные координаты её наблюдений были видны; рассчитанный центр остаётся отдельным маркером.
- [ ] Нажать на совпадающие радиомаркеры: список «Что здесь» открывается с камерой, центрированной на ближайшем маркере; выбор записи из списка открывает её карточку и переводит камеру на рассчитанный центр.
- [ ] При выборе точки нет вспышки/исчезновения всего слоя радиомаркеров, закрытия и повторного открытия карточки или рывков камеры во время анимации листа; fit bounds выполняется одним плавным переходом. После закрытия карточки viewport padding сбрасывается.
- [ ] Сверить историю: каждая запись с координатами имеет отдельный маркер; список отсортирован по RSSI от сильного к слабому (при равенстве — новые выше); выбор строки подсвечивает соответствующий маркер и переводит карту к нему в открытой области над карточкой.
- [ ] Тап по маркеру наблюдения выбирает соответствующую строку в карточке; записи без координат остаются в списке и не создают фиктивный маркер.
- [ ] Расчётный центр показан отдельным маркером; круг вокруг него соответствует расчётной погрешности и не подменяет исходные наблюдения.
- [ ] Проверить, что центр учитывает RSSI и точность; изолированный дальний выброс исключается; наблюдения по разные стороны антимеридиана остаются рядом.
- [ ] Для сотовой точки проверить добавление только свежей локально сохранённой записи OpenCellID с меньшим весом; устаревшая/чужая ячейка не участвует. Общая оценка BeaconDB не приписывается отдельному передатчику.
- [ ] Сохранённые активные зоны подписаны на карте; тап по подписи и по полигону открывает один и тот же редактор нужной зоны.
- [ ] Проверить редактирование названия, широты/долготы центра, радиуса и состояния enabled; после сохранения геометрия обновляется и остаётся после перезапуска.
- [ ] Проверить, что редактор корректно ограничивает радиус 25–100 000 м и не принимает некорректные координаты.
- [ ] Новая/изменённая геометрия плавно раскрывается от центра примерно за 460 мс; старые зоны не анимируются повторно при простом переключении enabled.
- [ ] Экспорт JSON и GeoJSON создаёт отдельные файлы; повторный импорт не удаляет существующие зоны, дубликаты пропускаются, конфликт ID разрешается новым ID.
- [ ] Проверить отказ импорта повреждённого файла, превышения лимита 2 МиБ, более 100 зон и некорректных координат.
- [ ] GeoJSON import/export проверен внешним валидатором; учитывается внешний контур Polygon (внутренние кольца/отверстия в этой версии не восстанавливаются).

Пункты этого раздела являются ручной проверкой P1.3–P1.4. Успешная компиляция и unit-тесты не заменяют проверку на реальном Android-устройстве.

## I. Источники и поиск радио-позиции (P2.1–P2.2, P2.7)

- [ ] При открытом приложении и выключенном мониторинге режим «Только радио» выполняет первый поиск сразу, затем не чаще раза в 60 секунд; поиск не продолжается после ухода приложения в фон.
- [ ] В режиме «Авто» foreground-поиск работает только при отсутствии активной геопозиции Android; после появления активного GPS/network фикса периодический радио-поиск прекращается.
- [ ] При включённом мониторинге foreground-сервис остаётся единственным владельцем периодических радио-сканов; дополнительный UI-цикл не запускается.
- [ ] Периодический поиск с выключенной записью обновляет текущую оценку, но не добавляет новые записи в историю radio observations/fingerprints.
- [ ] Если текущий поиск не дал оценки, OpenCellID используется как fallback только при включённых переключателях источника и сетевого доступа, сохранённом API-ключе, точном разрешении геолокации и выключенном safe mode.
- [ ] Проверить квоты OpenCellID на тестовом/контролируемом наборе: не более 3 ячеек на пакет, не чаще одного пакета за 15 минут и не более 100 попыток за UTC-день; HTTP 429 блокирует дальнейшие запросы до следующего UTC-дня.
- [ ] При наличии свежей локальной/кэшированной оценки OpenCellID fallback не вызывается; выключение любого согласия или удаление ключа прекращает новые внешние обращения, не удаляя сохранённые записи.
- [ ] Нажатие кнопки центрирования в режиме «Только радио» сначала обновляет радио, затем центрирует карту на полученной оценке; в «Авто» это происходит без активной Android-геопозиции, а также при опубликованном службой состоянии Auto→Radio даже если UI ещё содержит старую координату. При GPS-only и здоровом Auto обычное центрирование не запускает радио-скан.
- [ ] При переходах Auto GPS→Radio→GPS приватный флаг состояния в preferences своевременно включается/сбрасывается; после остановки службы он всегда сброшен.
- [ ] Ручная кнопка сканирования и периодический поиск не запускаются параллельно; ожидание уже идущего скана корректно завершает запрос центрирования.

Пункты этого раздела требуют проверки на реальном Android-устройстве; CI и unit-тесты не подтверждают фактические интервалы Android Wi‑Fi/CellInfo/BLE сканирования или доступность CellInfo на конкретной прошивке.

## J. Автоуточнение и пассивная запись Clear GPS DB (P2.3–P2.5)

### BeaconDB: уточнение существующих Wi-Fi-точек (P2.3)

- [ ] После чистой установки отдельный сетевой переключатель BeaconDB выключен; включение только переключателя автоуточнения само по себе не запускает запросы.
- [ ] Фоновое уточнение работает только при активном мониторинге, явном согласии BeaconDB, включённом переключателе автоуточнения и подтверждённой Wi-Fi-сети с доступом в Интернет; на мобильной сети запрос не выполняется.
- [ ] Проверить граничные условия питания: заряд 59% блокирует запрос, 60% допускает; температура 37,0 °C допускает, выше 37 °C блокирует. Неизвестные значения заряда/температуры закрывают путь.
- [ ] Кандидаты берутся только из одной недавней локальной Wi-Fi-выборки с минимум двумя различными BSSID; выбираются сначала точки с меньшим числом sightings и худшей точностью. Пустой/неизвестный SSID, `<unknown ssid>`, `0x` и суффикс `_nomap` исключаются.
- [ ] Проверить содержимое read-only lookup: передаются BSSID, RSSI, возраст и частота; SSID не сериализуется. Это запрос геолокации, а не публикация точки/наблюдений в базу вкладов.
- [ ] Успешный результат сохраняется как отдельная партия `auto_refined` с низким весом 0,20; он не добавляет строк в `radio_observations` и не становится fingerprint-обучением.
- [ ] Проверить backoff: успешный BSSID-набор не запрашивается повторно до срока backoff; HTTP 429 включает длительную паузу. Одна и та же неудачная точка не должна перехватывать все последующие попытки.
- [ ] Ручная координата `manual-edit` остаётся неизменной при автоуточнении. Удаление одной автоуточнённой точки и удаление всей партии BeaconDB удаляют только соответствующие производные данные и пересчитывают координату по оставшимся источникам.
- [ ] Выключение автоуточнения прекращает новые запросы и очищает партии BeaconDB; выключение основного сетевого разрешения блокирует сетевой путь независимо от состояния дочернего переключателя.

### OpenCellID: уточнение существующих локальных сотовых точек (P2.4)

- [ ] После чистой установки уточнение локальной базы OpenCellID выключено по умолчанию; включение требует отдельного переключателя, включённого источника/сетевого разрешения и сохранённого API-ключа.
- [ ] За один UTC-день выполняется не более 10 попыток; между попытками выдерживается не менее 2 ч 30 мин. Проверить границы интервала и сброс дневного счётчика на следующую UTC-дату.
- [ ] Кандидаты выбираются из уже существующих локальных сотовых записей, начиная с наименее часто наблюдавшихся/наименее точных; для одного кандидата не повторяется lookup до разрешённого срока backoff.
- [ ] Запрос содержит только поддерживаемый идентификатор сотовой ячейки и API-ключ. Wi-Fi/BSSID, RSSI, BLE, GPS-координаты и история наблюдений не отправляются; используется только read-only `GET /cell/get`.
- [ ] Найденный результат хранится как отдельная низкодоверенная партия `auto_refined`, не записывается в `radio_observations` и не становится training fingerprint. Проверить отдельные сроки backoff для found/not_found и обработку HTTP 429.
- [ ] Пользовательская координата `manual-edit` не меняется. Удаление партии OpenCellID удаляет только её автоуточнения и восстанавливает координату из оставшихся источников.
- [ ] При выключении любого обязательного разрешения, удалении API-ключа или включении safe mode новые сетевые попытки прекращаются; локальная история не удаляется сама по себе.

### Пассивная запись радиобазы (P2.5)

- [ ] После чистой установки «Пассивно собирать Clear GPS DB» выключено. После явного включения видны статус/уведомление foreground-сервиса и отдельная категория «Пассивная запись» с дневными партиями.
- [ ] Служба регистрируется только на Android `PASSIVE_PROVIDER`; в системной статистике/логах подтверждено, что Clear GPS не запрашивает собственные GPS/network fixes. Проверить получение callback только после того, как GPS-запрос сделал другое приложение.
- [ ] Принимается только GPS-фикс другого клиента: немоковый, точность от 1 до 10 м включительно, возраст от 0 до 15 секунд. Network-provider, mock, устаревший, неточный или некорректный фикс отклоняется.
- [ ] Проверить, что запись блокируется внутри зон спуфинга и аэропортового исключения; плохой/неточный фикс не создаёт новых строк.
- [ ] Wi-Fi и BLE записываются при перемещении не менее 30 м, соты — не менее 200 м. RSSI должен быть не слабее −70 dBm для Wi-Fi, −90 dBm для сот и −75 dBm для BLE; BLE ограничен устойчивыми iBeacon и Eddystone-UID.
- [ ] Каждая UTC-дата формирует отдельную партию. В общей пассивной истории действует жёсткий предел 500 000 наблюдений; после достижения лимита дальнейшая пассивная запись не увеличивает таблицу.
- [ ] С выключенным экраном пассивный сбор продолжается, если системный Battery Saver выключен и остальные условия PowerPolicy соблюдены. При включённом системном Battery Saver сбор останавливается; при включённом энергосбережении приложения порог низкого заряда также блокирует пассивный сбор. Проверить возобновление после восстановления условий.
- [ ] В категории «Пассивная запись» проверить просмотр, экспорт, отключение и удаление выбранной UTC-партии с подтверждением. Удаление одной даты не затрагивает другие даты, локальные ручные точки, импортированные источники и автоуточнения.
- [ ] Отключение функции снимает passive subscription и останавливает новые записи; повторный запуск не создаёт дублирующую подписку.
- [ ] Пассивные координаты/радиоидентификаторы не отправляются в сеть. Удалённые партии не должны появляться в BeaconDB/OpenCellID contribution endpoints; сетевые lookup остаются отдельными opt-in функциями.

Пункты раздела J — ручная проверка на физическом Android-устройстве. Unit-тесты и Linux/Windows CI подтверждают детерминированные политики/сборку, но не доказывают доставку PASSIVE_PROVIDER callback, фактические RSSI, поведение Android при выключенном экране, сетевой транспорт или энергопотребление.
 
## K. Ручное уточнение через BeaconDB и OpenCellID

### Общая вкладка «Уточнение»

- [ ] Раздел «Уточнение» доступен внутри вкладки «База» рядом с точками, историей и источниками; отдельного пункта «Уточнение» в нижней навигации нет. Переход в раздел не инициирует сканирование радиосетей.
- [ ] Настройки интервала и количества запросов сохраняются после перезапуска: интервал отдельно для каждого провайдера от 1 до 15 минут; максимум за один запуск от 1 до 10.
- [ ] Журнал показывает провайдера, время, статус, число уточнённых точек, найденные/не найденные записи, пропуски, ограничения и ошибки; перезапуск приложения сохраняет последние 200 событий.
- [ ] Проверить остановку очереди, отзыв разрешения во время работы и отсутствие второго параллельного запуска.
- [ ] Уточнённые координаты попадают в отдельные удаляемые партии `radio_auto_refinements`, не создают `radio_observations` и не изменяют `manual-edit`.

### Ручное уточнение BeaconDB

- [ ] При выключенном мастер-согласии кнопка не выполняет запрос; при включении без подтверждённой Wi-Fi-сети запуск также блокируется.
- [ ] Ручной запуск работает по уже сохранённым локальным Wi-Fi-выборкам и не требует активного мониторинга или нового аппаратного сканирования.
- [ ] Каждый запрос содержит BSSID/RSSI/возраст/частоту одной недавней выборки, не смешивает разные времена сканирования и не сериализует SSID.
- [ ] Проверить фильтрацию неизвестного/скрытого SSID и `_nomap`, минимум два BSSID, максимум 32 в одном запросе, локальный интервал 1–15 минут и максимум 1–10 запросов за запуск.
- [ ] Ответ оценивает место съёмки набора сигналов, а не точное место каждого роутера; результат с погрешностью выше 5 км и результат внутри зоны исключения отклоняются.
- [ ] Проверить журнал: успешная оценка, число уточнённых BSSID, кэшированный ответ без повторного сетевого запроса, отсутствие подходящих выборок и HTTP 429.
- [ ] Успешные и неудачные идентичности соблюдают backoff; повторный запуск не делает прежний запрос сразу снова.

### Ручное уточнение OpenCellID

- [ ] Без включённого OpenCellID, сохранённого личного API-ключа и отдельного сетевого разрешения запросы не выполняются.
- [ ] Ручной запуск выбирает только не-ручные сотовые точки, у которых есть локальные наблюдения из включённого источника; импортированные без локальных sightings и точки `manual-edit` исключены.
- [ ] Каждый запрос отправляет только один поддерживаемый Cell ID/RAT/MCC/MNC/LAC или TAC плюс ключ через read-only `GET /cell/get`; Wi-Fi/BSSID, BLE, RSSI, GPS-координаты и история наблюдений не отправляются.
- [ ] Настраиваемый интервал 1–15 минут соблюдается между запросами. Максимум одного запуска — 1–10, но общий предел ручного и фонового уточнения остаётся 10 попыток за UTC-день; проверить счётчик после перезапуска приложения и после полуночи UTC.
- [ ] Проверить found/not_found, кэш/TTL, HTTP 429 и прекращение очереди после серверного ограничения. Отрицательный ответ не создаёт координату.
- [ ] Координата из ответа проверяется на совпадение с запрошенной ячейкой и зоны исключения; ручные координаты остаются неизменными.
- [ ] При отключении сети/ключа очередь прекращается; лог показывает найденные/уточнённые/пропущенные ячейки без публикации сырых идентификаторов.

Пункты раздела K требуют физической проверки Android-устройства и реальных ответов провайдеров. Unit-тесты и CI не подтверждают работу API-ключа, сетевую доступность, фактические квоты сервера или качество координат.
